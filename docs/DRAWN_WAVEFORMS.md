# Drawn and computed waveforms as instruments (design note, #182)

Status: design accepted (#182). **Stages 1 to 4 are built, and the measured pass and stage 5 (steel guitar, FM percussion, synthetic spaces) too**, including stage 3, the draw surface (`site/draw.js`, `site/draw.css`, `site/drawn-user.js`): the `waveforms@1` schema, `site/engine/waveforms.js`, the pack adapter (`site/packs-kinds.js`, activation through `packs.activateSources` on Play),
the example pack `glyphcore/drawn-core` (`wt_drawn_bass`, `wt_drawn_choir`, `wt_drawn_electric`, `wt_drawn_viola`, `wt_drawn_cello`, and the computed kit `dr_kick`, `dr_snare`, `dr_hat_closed`,
`dr_hat_open`, `dr_clap`, `dr_tom`) and their tests. Everything else below stays "coming"
(the CLI render path, the code-bearing `instrument-models` kind, drawn pitch and filter envelopes, per-register shapes in the surface); the Strudel mechanisms in section 2 exist in unmodified Strudel and are verified there.

Aim (#182): sounds in the families the reference catalogues cover, made by our own engine from data and parameters, so no recording is copied or
shipped. Variation comes from parameter ranges and a seed, never from a file per sound. Related: #180 (device adapter contract), #183
(instrument gaps), #181 (CC0 soundfonts, the licensed alternative for real recordings), #91 (hooks/pack adapter allowlist), `docs/PACK_SPEC.md`.

## 1. The no-copy rule (binding for every stage)

- A drawn or computed instrument is **authored by a person or generated by an algorithm from parameters**. The stored form is control points,
  partial lists, parameter sets and envelopes: data, never audio.
- A reference sound (a real instrument, a catalogue sample) may be listened to and described with **coarse descriptors only**: fundamental pitch,
  length, attack and decay times, brightness (spectral centroid class), noise-to-tone balance, vibrato rate/depth, register range. The descriptors
  choose starting parameters and live in the pack as `descriptors{}` (informative, never used to resynthesize).
- Not stored, not shipped, not derived: sample data, spectrum frames, partial amplitude lists measured from one specific recording, impulse
  responses, or any resynthesis of a specific recording. A curve traced by hand over a displayed recording is a copy; a curve drawn from
  "bright, short, a bit hollow" is not. The draw surface (stage 3) never loads or shows a recording to trace.
- Procedure per instrument: write the descriptor sentence first, then pick the family model and parameters, then draw. The pack records the
  descriptor sentence and `origin: "drawn" | "computed"`. The licence is the repo's own (CC0-1.0 for the data, stated per pack).
- A critic check (section 8 stage 1 box): grep the pack for base64 audio, for `RIFF`/`data:audio`, and for arrays longer than the cap of
  section 4.

## 2. Which Strudel mechanisms take a custom wave (verified)

Verified against `@strudel/web` 1.3.0 / `superdough` 1.3.0 (`superdough/synth.mjs`, `wavetable.mjs`, `sampler.mjs`, `util.mjs`, read in the
installed package) and by a headless run (section 2.1). No Strudel file is modified; every path below is public API or a plain pattern.

| # | mechanism | how a drawn shape reaches it | good for | limits |
|---|---|---|---|---|
| A | `s("user").partials([...]).phases([...])` | the drawn cycle is analysed (DFT) into harmonic magnitudes and phases; superdough builds a `PeriodicWave` (`waveformN`, `synth.mjs`) | single-cycle leads, basses, organs, pads; no files, no fetch, works in the CLI and on strudel.cc | harmonic spectrum only (periodic wave is band-limited); no morph; the arrays ride in the program text, so keep them to 64 partials |
| B | `samples({wt_name: [url]})` then `s("wt_name").wt(pos)` | a generated WAV (frames of 2048 samples, mono) given as a `blob:` or `data:` URL; the `wt_` key prefix selects the wavetable voice (`registerSampleSource`, `sampler.mjs`); `frameLen` 2048 default | multi-cycle morph (`.wt` position, `wtattack`/`wtdecay`/`wtsustain`/`wtrelease` envelope on the position, `warp`/`warpmode`, `unison`, `detune`, `spread`) | the URL is fetched and decoded at play time, so the WAV must exist in the page (built in memory, see section 5); `tables()` only accepts `.wav` URLs, `samples()` with the `wt_` prefix does not filter |
| C | `samples({name: [url]})` then `s("name")` | a generated WAV as a plain one-shot or looped sample | percussion shapes, plucks with a baked envelope, anything a periodic wave cannot do | a buffer is audio in memory (never stored in the pack); pitch comes from `speed`/`note` repitching, so formants move with pitch |
| D | `registerSound(key, onTrigger, data)` and `registerWaveTable(key, tables, params)` | exported from `@strudel/web` (verified present); an `onTrigger(t, value, onended)` can build its own nodes, including `AudioBufferSource` over a computed `AudioBuffer`, no URL needed | family models (kick, hat) computed per hit from parameters | JavaScript code: it is a code ingredient under PACK_SPEC section 10.3 (sandbox, trust tier), so not the first stage |

Registers: for B and C the sample map may be `{ "c2": [url], "c4": [url] }` instead of a list; `getCommonSampleInfo` (`util.mjs`) picks the closest
note key and repitches the rest, for the wavetable voice too (read in code, not run). `n` then indexes within that register's list (variants).

Envelopes that Strudel already applies to any of A, B, C: amplitude ADSR (`attack decay sustain release`), pitch envelope (`penv pattack pdecay
psustain prelease`, `getPitchEnvelope`), filter envelope (`lpenv`, `lpattack`, ...), FM (`fm`, `fmh`, `fmenv`), vibrato (`vib`, `vibmod`),
`distort`, `crush`. An arbitrary drawn amplitude shape that ADSR cannot express is baked into mechanism C (one-shot) or computed in D.

## 3. Instrument model (what a drawn instrument is made of)

One instrument = one `id` + these parts, each optional except `cycle` or `morph`:

1. **Single cycle** (`cycle`): one period, N control points in [-1, 1] (spline or linear), resampled to 2048 on use. Maps to A (analysed) or to a
   one-frame B.
2. **Multi-cycle morph** (`morph`): 2 to 64 frames at positions 0..1. Maps to B; `.wt(pos)` and the `wt*` envelope sweep it. The adapter
   renders a frame between two drawn keyframes by spectral interpolation (computed, so the user draws 2 to 8 keyframes, not 64).
3. **Amplitude envelope** (`env.amp`): breakpoints `[t, level, curve]`. If it is expressible as ADSR, the adapter emits `.attack .decay .sustain
   .release` (exact); otherwise it bakes a one-shot (C). Also `env.pitch` and `env.filter` (curves to `penv`/`lpenv` parameters).
4. **Per-register variants** (`registers[]`): a note range each, with its own `cycle`/`morph` reference, gain and brightness (a different shape
   at the low end than the high end is how a bass or choir stops sounding like one pitched-down wave).
5. **Parameters** (`params{}`): the declared knobs with ranges (section 5), each mapped to a Strudel control or to a model constant.
6. **Variation** (`vary{}`): seed and per-parameter spread (section 5).

## 4. Pack kind `waveforms` (built: schema, engine module, pack adapter; #182 stages 1 and 2)

Consistent with PACK_SPEC section 5: a new row in `schemas/craftpack/1/kinds/index.json`, schema `kinds/waveforms.1.schema.json`, adapter
`packs.registerKind('waveforms', ...)`.

| kind | entry file holds | goes into | code | hosts | today |
|---|---|---|---|---|---|
| `waveforms` (built) | `{instruments[{id, title, family, origin, descriptors, license, cycle?, morph?, env?, registers?, params, vary?, notes?}]}` (the `waveforms@1` document) | at Play, for each instrument a program names: mechanism A emits `.partials/.phases`; B and C register an in-memory WAV with `ctx.samples(map)` under a `wt_<id>` or `<id>` key (the same activation point as `sample-source`, `packs.activateSources`); sound names go into intellisense | never (pure data) | site, cli | none |

A computed instrument has `model` instead of (or beside) `cycle`/`morph`: `{kind: kick|snare|hat-closed|hat-open|clap|tom, params: {...}, variants: 1..16}`. The parameter names and ranges are the section 6.1 table
(`FAMILIES` in `site/engine/drums.js`; `validate()` refuses a foreign parameter, `E_WF_UNKNOWN`, or one outside its range, `E_WF_PARAM`; the schema bounds only the shape, the per-family ranges are a `validate()` rule). The pack adapter renders
`variants` one-shots in memory (variant 0 is the declared set, the others draw each parameter from `vary.spread` with the seed) and registers them as `dr_<id>`; `s("dr_kick:2")` picks variant 2. A model is a one-shot sample (mechanism C), not a wavetable.

`waveforms@1` instrument, fields (sizes are caps checked by the schema, on top of section 10.2 limits; entry file well under 5 MB):

```json
{ "id": "choir-ah", "title": "Choir ah (drawn)", "family": "choir", "origin": "drawn",
  "descriptors": { "pitch": "c3-c5", "attack_ms": 180, "release_ms": 400, "brightness": "mid", "noise": "low", "vibrato_hz": 5.2 },
  "license": "CC0-1.0",
  "cycle":  { "points": [[0,0],[0.1,0.4],[0.35,0.9],[0.6,-0.5],[1,0]], "interp": "spline", "res": 2048 },
  "morph":  { "frames": [ { "pos": 0, "points": [...] }, { "pos": 1, "points": [...] } ], "interp": "spectral" },
  "env":    { "amp": { "points": [[0,0,"exp"],[0.18,1,"lin"],[0.6,0.8,"lin"],[1,0,"exp"]], "adsr": true },
              "pitch": { "points": [[0,-0.3],[0.12,0]] } },
  "registers": [ { "from": "c2", "to": "b3", "use": "morph", "gain": 1, "tilt": -2 }, { "from": "c4", "to": "c6", "use": "cycle", "gain": 0.9 } ],
  "params": { "vowel": { "min": 0, "max": 1, "default": 0.3, "to": "wt" }, "detune": { "min": 0, "max": 40, "default": 12, "to": "detune", "unit": "cent" } },
  "vary":   { "seed": 7, "spread": { "vowel": 0.15, "detune": 0.3 } } }
```

Caps (built, #182 stage 1; the same rules in `validate()` of `site/engine/waveforms.js`, which the site trusts, and in the JSON schema):
closed world (every object lists its fields, any other field is `E_WF_UNKNOWN`); at most 32 instruments; `points` 4 to 256 per curve, each
point a 2-number pair in -1..1; 2 to 8 keyframes; envelope 2 to 64 points; `registers` up to 8; at most 12 descriptors, 16 params, 16 spread
entries; every string capped (title 80, license 40, descriptor value 60, ids 48) and every map key matching `^[a-z][a-z0-9_]{0,23}$`; no string or
key may contain `data:`, `blob:`, `://`, `base64`, `RIFF` or `RIFX` (`E_WF_AUDIO`/`E_WF_KEY`); keys are printable ASCII; free strings (title, license, descriptor values) are printable ASCII plus a Latin allowlist (Latin-1 letters and Latin Extended-A/B, so names such as "Dvorak" with its accents and "Lodz" with its stroke survive), minus the compatibility forms that normalise to ASCII (the long s, ligatures) and with no combining marks, zero-width, fullwidth, emoji or other scripts (a schema cannot normalise unicode, so both paths use the allowlist, and `validate()` also re-tests the NFKC form), `RIFF`/`RIFX` match as written (lower-case "riff" is a music word) and `data:`/`blob:`/`base64` in any case; the document is at most 5 MB (`E_WF_SIZE`,
checked first) and at most 200000 numbers. A schema-valid file measures 3.3 MB at the ceiling (32 instruments, every array full, 20-character
numbers), so the schema alone keeps under 5 MB, and `validate()` checks the bytes anyway. One rule only `validate()` can state: a param
default lies in its min..max. `tests/site/waveforms_caps.mjs` runs 46 bypass fixtures (plus 7 good ones, including accented Latin credits) through both and fails if either accepts one. Family
names: the closed list in section 6 plus `drum-*` families of #182; unknown family is a warning, not an error.

Under #180: each family model exposes its parameter set with ranges as the device adapter contract's declared parameters, so the same
`waveforms@1` instrument is addressable by the engine worker (events `{s, n, onset, value}`) and by a rack. Under #91: the kind is data-only, so
it needs only a new allowlist entry for the kind itself, no `$code`. Mechanism D (`registerSound`) is a separate later kind (`instrument-models`,
coming, code-bearing, sandbox host section 10.4) and is not part of `waveforms`.

## 5. Variation from parameters, not from copies

- A family model is a small set of declared parameters with ranges (kick: pitch sweep start/end, sweep time, body decay, click level, drive; hat:
  noise colour, metallic partial set, filter freq, decay; pad: unison, detune, filter, morph position, attack). The ranges come from the
  descriptors, not from a recording.
- `vary{seed, spread}` draws every parameter from `default +/- spread * range` with a seeded generator (`mulberry32(seed + i)`), so
  `instrument:seed` is a reproducible kit of related sounds. Presets are named parameter sets, nothing else.
- For the drawn shapes, variation is applied **to the drawn data by a transform, never by another recording**: harmonic tilt, even/odd harmonic
  balance, phase scramble amount, spectral stretch (slightly inharmonic), formant shift, wavefold amount, symmetry. Each is a pure function of
  the drawn cycle plus a number, so one drawing yields a family and stays the author's own shape.
- Where the model is computed (noise, FM, modal partials, Karplus-Strong), nothing is drawn at all; the parameter set is the whole instrument.
- Per register the same instrument changes shape (section 3, item 4), which is the main defence against the "one wave pitched" sound.

## 6. First candidates: the instrument gaps listed on #183

#183 lists what the licensed sample sources do not cover. Drawn or computed shapes can supply a usable stand-in for some of these, and an
honest weak stand-in for others. The ratings are for a plain wave plus Strudel's envelopes, filters and FM, judged against how an ear separates a
real instrument, not against a spectrum match (which would need the copying this note forbids).

| gap | model | recipe of parts | realism from drawn shapes | verdict |
|---|---|---|---|---|
| choir | morph (formant-like frames: ah, oh, oo) plus unison and slow vibrato | 3 to 5 keyframes drawn for vowel shapes, `.wt` sweeps vowel, `unison` 4 to 8, `detune`, `vib`, slow `attack` 0.15 to 0.4, a little noise breath | pad-like "choir ahh" is achievable and usable behind a mix; it will not sing words or give a close solo voice (no consonants, no natural formant motion). `voxBank` (the vox pack) stays the route for words | decent as a pad, not as a voice |
| bass guitar (electric) | single cycle plus pitch and filter envelopes, per-register shapes | drawn cycle with strong 2nd and 3rd harmonic, `lpenv` pluck sweep, short decay, `penv` tiny drop on attack, a click layer; separate register shape below E2 | plucked finger or pick bass is close enough to sit in a mix; slides, ghost notes and fret noise are not modelled | good (the most real of the list) |
| electric guitar | drawn cycle plus `distort`, or Karplus-Strong in model D | bright cycle, `distort` amount as a parameter, filter envelope for pick, per-string register shapes, palm-mute as a short-decay variant | distorted rhythm chunks read well; clean arpeggios and bends are thin; chords need separate voices | fair distorted, weak clean |
| steel guitar (acoustic or pedal) | Karplus-Strong or modal partial model (D), inharmonic stretch via section 5 | a plucked-string model with decay per partial, body resonance as a fixed filter pair; for pedal steel a slow glide via `penv` | a convincing pluck needs the string physics of model D (code kind, later stage); with drawn cycles alone it is a plastic pluck | built (stage 4) as a per-note Karplus-Strong one-shot, rated stand-in: no bends or slides |
| solo viola | single cycle with per-register shapes plus vibrato and bow-attack noise | saw-like cycle with a drawn nasal formant, vibrato rate/depth (`vib`, `vibmod`), slow attack, a bow-noise burst layer, expressive swell via `wtattack` | the bowed attack and sustain character are the hard part: a drawn wave plus vibrato reads as "synth strings", not a solo viola | weak, lead-synth strings at best |
| solo cello | as viola, lower register shape, slower vibrato, stronger low formant | same recipe, lower registers, bow noise higher | as viola; low sustained notes are more forgiving than high ones | weak to fair in the low register |

For the bowed and choir cases the licensed route (#181 soundfonts, the `sample-source` kind, `glyphcore/vcsl`) remains the realistic answer; this
note's instruments are the "our own sound" option, labelled as such (`origin`, `family`, and a realism field so the browser never oversells one).
`realism: "stand-in" | "usable" | "good"` is a proposed informative field on each instrument (coming).

### 6.2 Measured: rack spectral pass (built, 2026-11-17)

Reading the table. The first run exposed real defects in the models, fixed before this table: the hats were too bright and aliased (naive square waves; now band-limited), the snare and
hat noise had no top roll-off, kick and tom carried DC and sub-20 Hz skirts, and the steel guitar and FM voices ran well above their class band (now low-passed). What remains is mix hygiene,
not sound: kick, snare, tom and bass leave 2 to 20 Hz energy (the repetition of the pattern) and low-end spill above the standard until the class hygiene hook is applied, and then pass; the
percussion class has no hygiene hook, so the FM clave (sub-20 Hz share) and the FM conga (its modulation difference tone lands near 64 Hz, below the class band) miss and are rated `stand-in` on the numbers.
The class assigned to each instrument is a judgment (tom against the `kick` class because its fundamental sits at the `perc` band edge; viola `lead`; cello `keys`), and the alias check of
the standard was not run. Ratings that stayed: bass guitar, electric guitar, drums `usable` (they pass with the hook, or raw), choir pad, viola, cello, steel guitar `stand-in` (they pass the
spectral limits but the ear test of section 6 is what rates them; a measurement cannot show that a viola reads as synth strings).

## 7. How each part maps (summary)

| part | Strudel mechanism | pack kind |
|---|---|---|
| single cycle | A (`user` + partials/phases), or one-frame B | `waveforms` |
| morph | B (`wt_` key, `.wt`) | `waveforms` |
| amplitude and pitch envelope | `.attack .decay .sustain .release`, `.penv ...`; baked C if not ADSR | `waveforms` (`env`) |
| per-register | note-keyed sample map for B and C | `waveforms` (`registers`) |
| variation | seeded parameter draw plus shape transforms, in the adapter | `waveforms` (`params`, `vary`) |
| family models needing code (Karplus-Strong, FM kit models) | D `registerSound` inside the sandbox | `instrument-models` (coming) |
| reference use | descriptors only | `waveforms` (`descriptors`, informative) |
