# EDM and dubstep: references, what each taught, and the shared foundations

Owner: `daw-sme`. Issues: see the EDM tracker issue (edm-core foundations, dubstep family, tutorial track). Pack `glyphcore/edm` (CC0-1.0).
This file is the shared ground for every EDM family in this repo: **edm-core** (this pack) and the families that build on it
(dubstep here; DnB, electro, house / techno / trance / big-room in `glyphcore/dnb-electro`, which imports edm-core instead of
duplicating it). Everything below is re-derived in our own CC0 code; no preset, sample or code is copied from any source.
Marking: **(S)** sourced (link given, the claim is what the page says), **(M)** measured here with the headless CLI, **(D)** our
design decision (reason given), **UNVERIFIED** = could not be confirmed from a primary source.

## 1. Sources and what each one taught

### Strudel and the audio engine (primary, the engine we run)
| source | what it taught | used in |
|---|---|---|
| [strudel.cc/learn/effects](https://strudel.cc/learn/effects/) (S) | `duckorbit` / `duckattack` / `duckdepth` are Strudel's sidechain (target orbit, return time in seconds, depth 0-1); `distort` is `"amount:volume:type"`; `compressor` is `"threshold:ratio:knee:attack:release"`; `ftype` 12db / ladder / 24db; filter envelopes `lpenv` / `lpattack` / ... per filter; `tremolo*` (sync in cycles, shape tri / square / sine / saw / ramp); `orbit` = one delay and one reverb per orbit | moves `sidechain`, `ducked`, `pump`, `ott`, `drive`; every rack |
| [strudel.cc/learn/synths](https://strudel.cc/learn/synths/) (S) | waveforms, noise (`white`, `pink`, `brown`), `fm` (index) / `fmh` (harmonicity ratio) / `fmattack` / `fmdecay` / `fmenv`, `vib` / `vibmod`, `wt_` wavetables (AKWF), `partials` | growl / screech FM layers, vibrato on leads |
| [strudel.cc/learn/signals](https://strudel.cc/learn/signals/) (S) | `sine`, `saw`, `tri`, `square`, `rand`, `perlin` 0-1, `.range`, `.segment`, `.slow` | automation lanes in the tutorial track |
| `@strudel/core` 1.2.6 `controls.mjs` JSDoc and `superdough` 1.3.0 `helpers.mjs` (`createFilter`) (S, read in `engine/strudel-cli/node_modules`) | a **per-voice filter LFO**: `lprate` (Hz), `lpsync` (periods per cycle; rate = cps x sync), `lpdepth` (x cutoff), `lpshape`, `lpdc`, `lpskew`, same for `hp*` / `bp*`; the LFO phase is song time (cycle / cps), so a wobble stays locked to the bar | move `wobble(sync, depth)`, growl racks |
| `superdough` 1.3.0 `superdough.mjs`, `synth.mjs`, `worklets.mjs` (S, local source) | the per-voice chain order (filters before `shape` / `distort`, then `compressor`, `postgain`); supersaw `detune` is the **total** spread in semitones across `unison` voices (centre +- detune / 2), default `unison` 5, `spread` 0.6, `detune` 0.18; duck is triggered at the trigger event's time per target orbit | reese (2 voices, 0.3 st = +-15 cents), supersaw racks, docs/RACK_STANDARD.md stage order |
| [Web Audio API (W3C)](https://www.w3.org/TR/webaudio/) (S, interfaces only) | `DynamicsCompressorNode`, `BiquadFilterNode` (12 dB/oct biquads, cascaded twice for `24db`), `WaveShaperNode` are what superdough builds per voice; parameter defaults were not in the fetched part of the spec (**UNVERIFIED** here) | why one voice can only compress downward (no multiband per voice) |
| [Strudel on Codeberg (uzu/strudel)](https://codeberg.org/uzu/strudel) (S) | canonical source, AGPL-3.0; the site loads `@strudel/web` 1.3.0 unmodified from unpkg | licence boundary (we never vendor modified copies) |

### Mixing and mastering
| source | what it taught | used in |
|---|---|---|
| [Spotify for Artists: loudness normalization](https://support.spotify.com/artists/article/loudness-normalization/) (S) | playback normalised to **-14 LUFS integrated** (ITU-R BS.1770); master true peak **below -1 dBTP**, louder than -14 LUFS keep below -2 dBTP; Premium levels Loud -11, Normal -14, Quiet -19 LUFS | genre targets `docs/genres/edm.json`, `dubstep-ukf.json` (suno-track-lab) |
| [K-system (Wikipedia)](https://en.wikipedia.org/wiki/K-system), Bob Katz, "An integrated approach to Metering, Monitoring and Levelling" (AES) (S for the existence and aim: calibrated monitoring plus meter ballistics to keep dynamic range) | K-20 / K-14 / K-12 reference levels (0 VU = -20 / -14 / -12 dBFS RMS) are the standard reading of the paper but were **not** in the fetched page: **UNVERIFIED** here. We use the idea: work with headroom, judge loudness on a calibrated scale, master last | headroom rules (one voice peaks <= -6 dBFS; mix bus with headroom; master does loudness) |
| [iZotope: mono vs stereo](https://www.izotope.com/en/learn/mono-vs-stereo.html) and search summary of iZotope / NI low-end articles (S, partly secondhand) | sub energy (40 Hz and below) is not localised and is prone to phase cancellation; Ozone Imager demo narrows <= 125 Hz to mono; crossover choices 80-150 Hz across sources | low end mono below **120 Hz** (engine/master `mono_below=120`, rack audit `side<120`), sub racks mono, supersaw `spread` only above a 180 Hz high-pass |
| [Ableton Live audio effect reference](https://www.ableton.com/en/manual/live-audio-effect-reference/) (S) | Compressor sidechain section: external sidechain source and a sidechain EQ "triggered by a specific band of frequencies"; Multiband Dynamics (29.26): up to three bands, the four types (downward / upward compression, downward / upward expansion); Glue Compressor (29.21) modelled on a classic console bus compressor; Saturator curve types | sidechain move design, 3-band OTT `.split` example, glue on the merge bus |
| [Xfer OTT release note (KVR, 2012-09-11)](https://www.kvraudio.com/news/xfer-records-releases-ott-multiband-compressor-for-windows-and-os-x-vst-and-au-19972) (S) | OTT is "a re-creation of a popular aggressive multiband upwards / downwards compressor setting" used by dubstep and electro producers | move `ott` (one band) and the 3-band split example |
| [LMMS manual: LOMM](https://docs.lmms.io/user-manual/en/effects/lomm) (S, open DAW) | an open OTT-style design: 3 bands, per-band upward (below threshold raised) and downward (above threshold reduced) compression, thresholds -72..0 dB, ratios 1-99, global Depth / Time / Auto / Mix; mix inside the device, not the chain dry/wet, because crossover filters cancel in phase | why our split OTT mixes at the merge, why per-band compressors |
| [Ardour manual: sidechaining](https://manual.ardour.org/signal-routing/sidechaining/) (S, open DAW) | sidechain = a dedicated send from the source to the processor's sidechain input; route the trigger through an EQ'd intermediate track for better triggering | our trigger is the kick event itself (duckorbit), no audio send needed; mixdown `follow` / `mbduck` for audio-level triggers (suno-track-lab engine/e2e) |
| [Bitwig: sidechaining tutorial](https://bitwig.com/learnings/sidechaining-tutorial-49) (S, via search summary) | sidechain inputs on Dynamics, Gate, Transient Control; sources pre / post fader or single drum pads; an "Audio Sidechain" modulator maps a signal's amplitude to any parameter | `.wire("gain", "kick:env")` (tap envelope to any param, docs/HOOKS_SYNTAX.md) as the modulator form |
| [LMMS compressor](https://docs.lmms.io/user-manual/en/effects/compressor) and forum (S, via search summary) | LMMS historically used the Peak Controller as a sidechain workaround; true sidechain support was being merged in 2024 (**UNVERIFIED** for the current release) | none (context) |

|---|---|---|

| [Ableton Live instrument reference: Operator 31.9](https://www.ableton.com/en/manual/live-instrument-reference/) (S) | FM: a modulator's level sets brightness ("higher levels usually create bright and/or noisy sounds"); Coarse = whole-number ratios (harmonic), Fine = fractional (inharmonic); feedback; FM aliases easily | growl `fmh 1` / `2` (harmonic), screech `fmh 3.01` (slightly inharmonic edge), FM index envelopes; the aliasing check on screech |
| [Surge XT manual](https://surge-synthesizer.github.io/manual-xt) and changelog (S, via search summary) | wavetable Morph crossfades between frames; FM2 / FM3 oscillators are a carrier with 2 / 3 modulators | conceptual: our "morph" is a vowel / formant sequence and an FM index envelope, since superdough has no frame morph; wavetable growl with `wt_` samples is **coming** (needs a sample bank) |
| [Vital](https://vital.audio/) and third-party write-ups ([MusicRadar](https://www.musicradar.com/news/vital-is-an-eye-catching-spectral-warping-wavetable-synth-plugin-that-you-can-have-for-free), [LANDR](https://blog.landr.com/vital-synth)) (secondhand) | spectral warp / wave morph modes, FM and ring-mod between oscillators; the official manual was not found (**UNVERIFIED** details) | conceptual only |
| [UKF: bassline dictionary, dubstep (Matthew Chapman)](https://ukf.com/read/bassline-dictionary-dubstep/) (S) | five described basses: syncopated sub with an 8-bar filter sweep; PWM square + saw with a filter envelope ("mwoooap"); hybrid wavetables with pitch modulation and resonance; vocal-like wavetables with a 1/16 synced LFO on cutoff plus a vowel filter ("talking"); a separate sine / triangle sub under wavetable layers with LFO-driven notch / band-pass and tube distortion | growl = separate sub + mid layer (`band split by layering`), `formantGrowl` (vowel sequence + synced LFO), `wobbleBass` (synced LFO), the 8-bar filter-sweep build |
| [Modern Drummer: pocket dubstep drumming, part 1](https://www.moderndrummer.com/2014/03/video-pocket-dubstep-drumming-part-1-basics-may-2014-issue) (S) | dubstep tempos "range between 138 and 142" bpm; half-time: kick emphasises only the 1, snare / clap on beat 3, hats keep the standard meter (a double-time sensation) | `ds.halfKick`, `ds.halfSnare`, the halftime feel, 140 bpm |
| Search results on dubstep / EDM arrangement ([Future Proof](https://futureproofmusicschool.com/blog/how-to-make-dubstep-the-ultimate-beginner-s-guide), [EDMProd](https://www.edmprod.com/how-to-make-dubstep/), [homebrewaudio](https://www.homebrewaudio.com/how-to-structure-a-dubstep-track/)) (secondhand, general) | intro, build, drop, breakdown, build, drop, outro in 8 / 16 / 32 bar blocks; breakdown removes kick and bass; second drop varies the first (harder, new bass timbre or rhythm); a fill or roll right before the drop | the 104-bar map (section 3), `ec.switchUp` |

## 2. Shared foundations (edm-core; what the other EDM families reuse)
Racks and moves live in `site/data/edm/racks-edm-core.json`, atoms (`ec.`) in `atoms-edm-core.json`, generated from
`tools/concepts/families/edm-core.json`. Import with `atoms.import("pack:glyphcore/edm:atoms-edm-core")`.

| topic | rule (D unless marked) | where |
|---|---|---|
| tempo | dubstep / UKF / riddim 140 bpm half-time (S, Modern Drummer); one cycle = one bar of 4/4 (`setcpm(140/4)`) | all recipes |
| sidechain | the kick carries `sidechain(orbit, depth, release)` (= `duckorbit`, `duckdepth`, `duckattack`), the ducked parts carry `ducked(orbit)` (= `orbit`). Defaults: depth 0.8, release 0.2 s (a 140 bpm beat is 0.43 s, so the duck recovers inside the beat). Rejected: a tap wire on every voice (`pump` in phonk, `.wire("gain","kick:env")`): it re-queries the kick per voice and does not lower to plain Strudel; kept for non-kick triggers | `edm-sidechain-duck` |
| pump without a trigger | `pump(depth)`: `tremolosync 4`, `tremoloshape ramp`; a volume shaper (LFOTool-style) that works on held chords and in breakdowns with no kick. Rejected: a velocity table (needs 16th-segmented notes) | `edm-pump-shaper` |
| risers | length is a parameter in seconds (`len = bars x 240 / bpm`: 4 bars at 140 = 6.86 s, 8 = 13.71 s, 16 = 27.43 s); `noiseRiser` (fade in + low-pass opens 4 octaves), `hpBuild` (high-pass climbs, the "white-noise build"), `pitchRiser` (2-octave glide), `reverseSwell` (fades in, stops dead), each ends on the drop. Riser grammar gates `ec.rise4 / rise8 / rise16 ({ at })` end exactly on the point | `edm-noise-riser`, Syntax "8-bar build grammar" |
| builds | snare roll `ec.roll8` (quarters x2, eighths x2, sixteenths x3, 32nds) with `ec.rollVel8`; filter automation `ec.open8` (lpf x1.5 per bar, 300 Hz -> 6 kHz) and `ec.thin8` (hpf, 30 -> 800 Hz); the breath `ec.gapMask` / gate `ec.gap` (the last beat before the drop is silent: the release is the contrast) | `edm-build-grammar` |
| impacts | `impactBoom` (C1 + 2-octave drop), `subDrop` (130 Hz -> C1 over 1 s), `crash` on the downbeat, `downSweep` after it; gate `ec.hit({ at })` | `edm-impact`, `edm-sub-drop` |
| bus processing | per voice superdough has only downward compression (`ott` move = deep fast squash + makeup, one band). Multiband (3-band OTT) and band-split distortion are `.split` branches on superdough buses (docs/LANES.md): `lo => lo.lpf(120)` stays clean and mono, `mid => mid.hpf(120).distort(..)`, `hi => hi.hpf(2500).compressor(..)`, `.merge(m => m.compressor(..))` is the glue. Strudel has no linear-phase crossover, so the bands overlap at the crossovers (two 12 dB/oct slopes): **(M)** the sum is not flat; mix by ear | Syntax "Band-split drive and 3-band OTT" |
| low end | everything under 120 Hz is mono: sub and kick have no `spread` / `jux` / `pan`; supersaws high-pass at 180 Hz before their `spread`; growl and reese layers high-pass where the sub takes over (the band split by layering: the sub plays the fundamental, the mid layer starts at 70-100 Hz) | rack audit `side<120`, master `mono_below=120` |
| headroom and loudness | each rack peaks at -6 dBFS or lower (kick, snare, impact -3) (RACK_STANDARD); the mix bus keeps headroom; loudness is the master's job (`engine/master/master.py --preset dubstep`, -8 LUFS target, true peak -1 dBTP ceiling). Streaming plays at -14 LUFS (S, Spotify), so a -8 LUFS club master is turned down 6 dB there: loudness buys nothing on streaming, density and transients do | docs/genres targets |
| arrangement | 8-bar phrases, 16-bar sections; every section change has a fill or a gap; energy rises in builds by adding density (roll subdivisions), brightness (filter open) and level (risers), and falls after the drop's first bar by nothing (the drop holds); breakdown = no kick, no sub | section 3 |

## 3. The 104-bar map (gates `ec.*`) and its energy curve
Energy is our own 0-10 design scale (D), set by density (onsets), bandwidth (filter) and level; the tutorial measures what it really does.

| bars | gate | content | energy |
|---|---|---|---|
| 1-16 | `ec.intro` | atmos pad, filtered chords, hats in at bar 9, no sub | 2 -> 3 |
| 17-24 | `ec.build` (`rise8({ at: "25b" })`) | snare roll, noise riser, filter opens, high-pass thins, `gap` on the last beat | 3 -> 8 |
| 25-40 | `ec.dropA` | half-time kick / snare, sub + growl / reese, sidechain, impact and crash on bar 25 | 9 |
| 41-56 | `ec.breakdown` | no kick, no sub; supersaw chords, pluck / lead, vowel chops, pump without trigger | 4 -> 5 |
| 57-64 | `ec.build2` | roll + white-noise build + pitch riser, gap | 5 -> 9 |
| 65-88 | `ec.dropB`, `ec.switchUp` 77-88 | drop B with a different bass (riddim / formant), switch-up at 77 | 10 |
| 89-104 | `ec.outro` | drums and atmosphere, bass out, downlifter | 4 -> 1 |

## 4. Not covered (coming or out of scope)
- Wavetable frame morphing (Serum / Vital style) needs `wt_` sample banks: **coming**; we use vowel sequences and FM index envelopes instead.
- Real vocal chops need a vox bank (`glyphcore/vox`, licences in that pack); the dubstep family's `vowelChop` is a synthesised vowel stab.
- True upward compression per band: superdough's compressor is downward only; the `ott` move approximates with makeup gain (D).
