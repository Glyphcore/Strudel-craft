# Packages: where content comes from, folders, tags and appearance

Informative reference for issue #120. It audits which catalog, atom, rack, feel and groove entries live in which pack, describes the folder / tag / taxonomy
data model and the tag-driven appearance, and lists what was migrated and what waits. Spec: docs/PACK_SPEC.md (sections 3, 5.3, 9.3, 13). Add-a-concept checklist: docs/CONVENTIONS.md section 7.

## 1. The package paradigm today (answer to "do recipes live under our namespace?")
Mostly yes, with one provisional exception. Three packs ship in `site/packs.lock.json`:

| pack | where | version | licence | holds |
|---|---|---|---|---|
| `glyphcore/phonk` | `site/data/phonk/` (`craftpack.json`) | 1.3.0 | CC0-1.0 | atoms (`ph.`, `ph2.`, `hh.`, `dt.`), racks, dovetail moves, five feel templates, groove presets, the night phonk track recipes |
| `glyphcore/vox` | `site/data/vox/` | 1.0.0 | per ingredient | vox bank index and word maps |
| `glyphcore/shim` | `site/craftpack.json` over `site/data/*` | 1.0.0 | `LicenseRef-undecided` | the catalog recipes (87), Syntax examples, intellisense, param shapes, control types, docs |

`glyphcore/shim` is a **provisional pack**: PACK_SPEC 14.3 step 2 puts today's `site/data/*` behind a pack manifest so the loader runs unchanged, and P4 (#69) replaces it with
`glyphcore/core`. P4 is blocked on the licence decision (#66; the registry refuses `LicenseRef-undecided`, spec section 7), so the 87 catalog recipes carry namespaced ids
(`glyphcore/shim:four-on-the-floor`, bare `four-on-the-floor`) but not yet a final home or licence. Moving the catalog file now would break its consumers (the build
tools, the lowering check, the rack audit, six test suites) and pre-empt #66 / #69, so it was not moved; the ids are stable and aliases (section 5) carry any later rename.

Reading the table:
- **Real pack**: atoms, racks, feels and the night phonk recipes are `glyphcore/phonk` items with version 1.3.0 and CC0-1.0. Ids are `glyphcore/phonk:<item>`.
- **Provisional**: the catalog recipes (hand-written 46 from RECIPES.md / `build_catalog.py`, generated 41 from `tools/concepts/families`) are `glyphcore/shim` items, ids `glyphcore/shim:<id>`.
- **Orphans**: the four Perform presets (`data/perform/presets.json`; the pack kind `perform-presets` is *coming*, spec section 5, no adapter yet) and the four workspace layouts (`DEFAULTS` in `workspace.js`; the kind

- **Engine built-ins**: the nine groove presets of `engine/groove.js` are the standard library (they must work with `--no-packs`).

## 4. Data model: folder and tags
Fields (spec 5.3): `folder` (slash path, 1-8 lowercase segments), `tags` (lowercase kebab, up to 24), `aliases`. Validation: `python3 tools/packs/packs.py validate DIR`:
a bad folder is `E_PACK_FOLDER`; a tag outside the pack's `taxonomy.tags` is `W_PACK_TAG`; packs without these fields are unchanged (`tests/packs/taxonomy.py`).

**Derivation** (`tools/concepts/taxonomy.mjs`, used by `tools/concepts/build.mjs` and `tools/packs/taxonomy_fill.mjs`; nothing is typed by hand):

| field | from |
|---|---|
| folder, recipes | family and role: `hiphop/<trap|boom-bap|hyphy|cloud|general>/<drums|bass|keys|pad|lead|vox|fx|form|feel>`, `dovetail/<technique>`, `groove/<swing|push|human>`, hand recipes `strudel/<role>`, night phonk `phonk/tracks` |
| folder, atoms | namespace and name: `hiphop/trap/drums`, `dovetail/pickup`, `feels/<feel>/<role>`, `phonk/form` |
| folder, racks | class: `racks/<role>`, moves `dovetail/moves`, groove presets `grooves/presets` and `grooves/builders` |
| tags | role (`drums bass keys pad lead vox fx form groove dovetail`), genre (`hip-hop trap boom-bap hyphy cloud phonk`), feel (`feel`), tempo-feel (`half-time syncopated offbeat four-floor polyrhythm`), mood (`dark driving hypnotic tense floaty sparse bright`), technique (the catalog labels and `rack`, `rack-slot`, `gate`, `pattern`), status (`verified unverified needs-samples lowered approx`) |

`taxonomy` in each manifest lists the tags that are used, each with a `group`, and the groups with a title; `taxonomy.priority` is roles first, then genre, feel, tempo, mood, technique, status.

## 5. Aliases
`aliases: ["old-id"]` on a recipe, atom or hook def (and `meta.aliases` on a library component). `packs-core.resolve` adds `resolution[kind][alias] = { winner, shadowed, alias: true }` for every alias no item of that kind owns.
Use it when an entry is renamed or moves between packs (for example the catalog moving from `glyphcore/shim` to `glyphcore/core` keeps every bare id). Test: `node tests/packs/aliases.mjs`.

## 6. Appearance by tag
`site/engine/taxonomy.js` resolves a style `{ color, icon, pattern?, badge? }` for tags, entries and folders; the chain and the palette are specified in PACK_SPEC 5.3.
- **Palette**: 12 fixed keys, tokens `--tx-<key>` and `--tx-<key>-bg` in `site/taxonomy.css` (generated, dark on `:root`, light under `:root[data-theme="light"]`), every pair at least 4.5:1 on the panel surfaces in both themes
  (`gen_taxonomy_css.py` refuses to write otherwise; `tests/site/taxonomy.mjs` re-checks the file and the rendered chips).
- **Not colour only**: every style draws an icon, and chips and breadcrumbs print the tag name; folders print their name and count.
- **Default by category**: a tag with no style takes its category (drums orange drum, bass rose, lead amber, pad violet, keys indigo, fx cyan, vox lime, form blue, feel rose, groove teal, dovetail cyan, genre amber, status green), then neutral slate.
- **User override**: Folders and tags > Appearance opens the site modal: pick the tag or folder, a colour from the fixed set, an icon and a pattern; stored in `localStorage sc.taxonomy` `styles` and exported with the rest.

## 7. UI, deep links, CLI
- Recipes (`site/organizer.js`, mounted in `app.js`), Syntax (`syntax.js`) and Banks (`voxbrowser.js`) share one organizer: collapsible folder tree with counts, breadcrumbs, tag chips with Match all / any, sort (catalog, name, folder, pack),
  search over names, tags and folder paths, a pack badge on every row, targets of 44 px at 390 px. Presses never focus or scroll the editor (#107). The state persists (`sc.org.<view>`).
- Deep links: `#folder=hiphop/trap&tag=drums,kick&mode=or` (Recipes). A `#r/<id>` link is not combined with a filter link.
- User organization: Inspector > Folder and tags (site modal) moves a recipe to a folder and adds your tags; Folders and tags > New folder, Appearance, Export, Import. The document is `taxonomy@1`
  (`{ folders[], entries{"recipe!id": {folder, tags}}, styles{} }`); the same keys serve takes (`take!id`), library components (`component!name`) and atoms (`atom!name`) through `strudelCraft.taxonomyStore`
  (`move`, `tag`, `setStyle`, `exportJSON`, `importJSON`). The Perform view and the Atoms browser do not render the tree yet (those files are being changed by other work); the data and the API are in place.
- CLI (in `engine/strudel-cli` of the suno-track-lab checkout, same rules as the site, `$STRUDEL_CRAFT/site/engine/taxonomy.js`): `strudel packs list --folder hiphop/trap --tag drums [--any-tag a,b]`,
  `strudel library list --library DIR --tag drums`, `strudel complete tag:dr` (tags and folders with counts). Test: `node tests/packs/cli_taxonomy.mjs`.
