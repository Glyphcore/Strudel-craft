# 01 SOT protocol (read first). Terse by design; this file is itself a spec body: reach it via HANDOFF.md fold.

## Principle
Two layers per unit: FOLD (one line, always cheap) and SPEC (detailed, gated). Agents consume folds; they pull a SPEC only for ids they are about to change or verify. Verbosity is never exposed by default and the gate is stated once, tersely, in a header.

## Layout (recommended; you may change it if requirements A-E hold)
- spec/folds/<area>.md : header + FOLD lines only (no bodies).
- spec/specs/<id>.md : the detailed spec for one unit (own file => cannot leak through a grep of folds).
- spec/flows/<flow>.md : UI flow graphs (nodes, edges) as folds + spec files.
- spec/ledger/pre.md, spec/ledger/post.md : concern ledger, fold lines only; detail in spec/specs/C-<n>.md.
- spec/index.json : generated by `sot gen-index`; machine lookup (id -> file, guid, st, tags, issues, evidence, bytes of spec).
Requirements: A) default read path shows only folds. B) the gate command is printed in every header in <= 1 line. C) a spec body is reachable only by explicit id. D) every output carries a frame header (below). E) `sot check` fails CI-style on violations.

## Unit record (fold line)
`@U <id> g=<guid8> st=<state> tags=<a,b> iss=<#n,...> ev=<path@sha|test,...> | <fold text <= 160 chars>`
- id: `sc.<area>.<feature>[.<aspect>]` lowercase, dot-separated, immutable. Rename via `aka=<old id>`; never reuse an id.
- guid8: 8 hex, derived once (sha1 of id + creation date), immutable, shown so renames stay traceable.
- st: planned | building | review | accepted | regressed | deprecated | unverified.
- ev: evidence refs; accepted needs >= 1 test or measurement ref + the closing issue; unverified must say why.
- Concern ids: `C-<nnnn>` (ledger). Flow ids: `sc.flow.<name>`. Decisions: `D-<nnn>` in handoff/decisions.md.

## Spec body (specs/<id>.md)
Fixed headings, short bullets, no prose padding: Intent / Behaviour (observable) / Interface (API, syntax, data shape) / Impl type (stack, module kind, where it runs, perf budget) / Acceptance (testable bullets) / Edge cases / Non-goals / Links (ids, issues). Impl type states HOW at a level a rebuild needs (e.g. "lazy ES module, no deps, loaded after first paint, hash-pinned data file"), not source code.

## UI flow catalog
Nodes = screens/sheets/panes/modals/toasts with id `sc.flow.<flow>.<node>`; edges = user actions (tap, long-press, key, deep link, palette cmd) with guard + result; each node lists the feature ids it hosts and its phone constraints (390px, 44px targets, no scroll-on-press). Deep links and URL hashes are first-class entries.

## Frame / header convention (outputs and tool calls)
Every `sot` output starts with one frame line:
`⟦sot v1 | cmd=<cmd> | view=fold|spec | n=<items> | gate: sot spec <id> | filter: sot ls --st=<s> --tag=<t> --area=<a>⟧`
Agents quote ids, not prose. Agent reports to the main session start with `⟦sot v1 | touched=<ids> | st=<delta> | iss=<#> ⟧` then <= 8 lines. Issue bodies/comments from tearline on include one line `sot: <ids>`.

## CLI (tools/sot/, Node, zero deps, tested)
`sot ls [--area A] [--st S] [--tag T] [--iss N]` fold lines | `sot fold ID` | `sot spec ID` (only way to print a body; prints size first) | `sot find TEXT` (folds only) | `sot ledger [--pre|--post] [--open]` | `sot check` (grammar, unique ids/guids, evidence rule, orphan refs, folds <= 160 chars, specs only in specs/, headers present, ledger links resolve) | `sot gen-index` | `sot tearline` (prints tearline marker and counts of units/concerns touched after it) | `sot touch ID --st S --ev REF` (state change with evidence, appends history).
History: spec/history.jsonl append-only (id, st, ev, date, by) so "state of a feature at time T" is answerable.

## Anti-leak rules
- Folds never contain bodies, never contain verbose directives.
- Directive text (this protocol, how to think) lives in skill/agent bodies as folds with detail behind `sot spec`; CLAUDE.md carries <= 12 lines.
- Seed files (seed/directives.md) are inputs; after consolidation the ledger is the source and seed is archived under seed/archive (kept, never read by default).
