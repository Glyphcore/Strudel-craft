# Craftpack tools (`tools/packs/packs.py`)

Offline reference implementation of the pack commands of `docs/PACK_SPEC.md` section 12 (issue #65).
The `strudel` CLI lives in another repository (`engine/strudel-cli`, suno-track-lab); it is **not** in this
checkout, so `strudel packs ...` cannot be run here. This file is the same behaviour, same error codes and
same exit statuses, runnable with Python 3 + `jsonschema` alone; the CLI subcommands `strudel packs
validate | hash | lock | registry build | registry check | --api` wrap it (status: coming, see #68).

```
python3 tools/packs/packs.py validate DIR|craftpack.json [--strict]
python3 tools/packs/packs.py hash DIR [--write] [--check]
python3 tools/packs/packs.py lock [packs.json] [-o packs.lock.json] [--update ID] [--frozen]
python3 tools/packs/packs.py registry build DIR -o index.json [--github OWNER/REPO@COMMIT]
python3 tools/packs/packs.py registry check index.json
python3 tools/packs/packs.py --api            # host pack API version (1.0.0)
```

Exit status: `0` clean, `1` at least one `E_` diagnostic (or a `W_` under `--strict`), `2` usage.
Every diagnostic prints as `CODE where: message` with the codes of PACK_SPEC section 13.

| command | what it checks or writes |
|---|---|
| `validate` | manifest against `manifest.schema.json`, each entry file against its kind schema (`schemas/craftpack/1/kinds/index.json`), paths confined to the pack root, the whole hash tree (entry files, modules, asset index, assets), code flags, ingredient and item id uniqueness, `requires` vs `dependencies`. On a folder holding `packs.json` it resolves the request instead (dependency codes). |
| `hash` | recomputes entry/module hashes and sizes and the `sha256sum`-format asset index; `--write` updates `craftpack.json` and the index, `--check` exits 1 when anything is stale |
| `lock` | resolves `packs.json` to `packs.lock.json`: `github:` refs become 40-hex commits, dependencies are resolved once (highest version satisfying every range, one version per id), output is deterministic and schema-valid; `--frozen` exits 1 when the lock on disk would change |
| `registry build` | walks a folder of packs, validates each (invalid ones are skipped with their codes on stderr) and writes an index that validates against `registry.schema.json` |
| `registry check` | schema, namespace rule (`E_PACK_NAMESPACE` when a `github:` source sits under another owner), refuses a missing licence or `LicenseRef-undecided`, and for local `file:` entries re-checks the manifest hash and the `code` flag |

Shared resolution (bare-name precedence, shadowing, the report) is **not** here: it is one DOM-free, Node-free
ES module at `site/engine/packs-core.js`, imported by both hosts the way `site/engine/hooks.js` is.

`tools/packs/shim.py` (`--check`) keeps the site's shim pack (`site/craftpack.json`, `site/packs.lock.json`, #67) in step with `site/data`.

## Tests

```
python3 tests/packs/schemas.py          # schemas are valid draft 2020-12; the examples validate
python3 tests/packs/sitedata.py         # current site/data validates against its kind schemas
python3 tests/packs/gen_assets.py       # (re)generate the synthetic fixture audio, then:
python3 tools/packs/packs.py validate tests/packs/fixtures/good
node tests/packs/core.mjs               # tests/packs/vectors.json against site/engine/packs-core.js
```

Fixture audio is tiny synthetic WAV generated by `gen_assets.py` and git-ignored: no pack content (samples,
vocals) is committed while the first-party content licence is open (#66).

## Known gaps

- `E_PACK_LICENSE` (registry refuses a missing or undecided licence) has no code in PACK_SPEC section 13,
  which lists only the `W_PACK_LICENSE` warning. Noted on #65 rather than diverging silently.
- `packs install` / `verify` / `list` (fetching and caching) belong to the CLI loader, #68.
